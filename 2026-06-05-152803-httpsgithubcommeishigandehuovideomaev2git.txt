  python run_mdpe_finetune.py

  lr=5e-5）自动开始训练。如果想用 WandB 记录，加上 --no_wandb 可以关闭。

  典型单卡运行命令：

❯ 2进程 × 1份 × 88GB，两进程是什么意思                                          
  ⎿  ⧉ Selected 4 lines from .vscode/settings.json in Visual Studio Code

  Thought for 51s (ctrl+o to expand)

● 双卡 DDP 训练时，torchrun --nproc_per_node=2 会启动 2 个独立的 Python 
  进程，分别绑定 GPU 0 和 GPU 1。

  每个进程各自加载一份数据到内存：
  - 进程 0（GPU 0）：88GB
  - 进程 1（GPU 1）：88GB
  - 总计：176GB

  这是 DDP
  的机制——每个进程有自己独立的内存空间。如果想进一步减少内存占用，可以改用 mmap
  方式加载数据（让两个进程共享同一块物理内存），但实现更复杂。目前 176GB
  的话，200GB 内存应该够用了。

● num_workers > 0 报错，很可能是因为内存不够。

  原因：DataLoader 每启动一个 worker 子进程，都会复制 Dataset 对象。你的 Dataset
   里 self.videos 持有整个 88GB 数据。以 num_workers=4 为例：

  - 每个 GPU 进程的 DataLoader 有 4 个 worker
  - 每个 worker 都会持有 88GB 数据的引用
  - 2 个 GPU 进程：2 × 4 × 88GB = 704GB 内存需求

  实际上 Linux 用 fork 时是 copy-on-write，不会立即复制全部内存，但 Python
  的垃圾回收和内存碎片化会导致实际占用远超预期，200GB 就不够用了。

  解决方案：数据不放在 Dataset 对象里，改用共享内存，让所有 worker
  只读同一份数据。要改吗？

❯ 启梯度检查点默认值起到什么作用                                                
  ⎿  ⧉ Selected 4 lines from .vscode/settings.json in Visual Studio Code

  Thought for 10s (ctrl+o to expand)

● 梯度检查点（Gradient Checkpointing）的作用是用计算时间换显存。

  正常训练时，前向传播会把每一层的中间激活值保存在显存里，等反向传播时用来算梯度
  。这些激活值占用大量显存。

  开启后，前向传播只保存部分关键层的激活值（检查点），其余层的激活值在反向传播时
  重新计算。这样：

  - 显存降低：大约减少 30-50% 的显存占用
  - 速度变慢：因为要重新计算被丢弃的激活值，训练速度会慢约 20-30%

  对于显存不够的情况，这是一个很好的权衡。

● 逐一解释：

  #1 EMA 更新时机
  EMA（指数移动平均）是维护一个模型参数的"影子副本"，用于更稳定的推理。原始代码
  每个 training step 都更新一次 EMA（一个 epoch 有 379 次），你的代码每个 epoch
  结束才更新一次。导致 EMA 模型跟不上训练进度。

  #2 验证集分布式聚合错误
  双卡训练时，每张卡各自验证一部分数据，然后需要把结果汇总。当前代码汇总逻辑有
  bug，_total 变量从未设置，导致双卡验证准确率计算错误。

  #3 AMP dtype
  AMP 是混合精度训练。原始代码用 bfloat16（范围大、精度低），你的用
  float16（范围小、精度高）。bfloat16 更不容易溢出。

  #4 cudnn.benchmark
  开启后 CuDNN 会自动寻找最快的卷积算法，加速训练。不影响结果。

  #5 验证时 AMP
  原始代码验证时也用混合精度（省显存、更快），你的代码验证时用全精度。

● update_freq 是梯度累积的意思——不用增大 batch size 也能模拟大 batch。

  比如 batch_size=4, update_freq=2：
  - 实际每次只送 4 个样本进 GPU（显存占用小）
  - 但连续做 2 次前向+反向，把梯度累加起来，再更新一次参数
  - 效果等同于 batch_size=8

  但你的代码没有实现这个功能（缺了 loss /= 
  update_freq、条件判断等逻辑），所以如果把 update_freq 改成大于
  1，训练结果会不对。

  结论：想增大 batch size 就直接改 --batch_size，不要动
  update_freq。如果显存不够用更大的 batch size，保持现在的设置就行。

❯ ddp和普通的dataparral有什么不同                                               

● DataParallel (DP)
  - 单进程，多线程
  - 数据自动拆分到多卡，结果汇总到主卡
  - 主卡负载重（梯度汇总、参数更新都在主卡）
  - 简单，model = nn.DataParallel(model) 一行搞定
  - 受 Python GIL 限制，效率低

  DistributedDataParallel (DDP)
  - 多进程，每张卡一个独立进程
  - 每个进程独立加载数据、前向、反向
  - 梯度通过 NCCL AllReduce 同步，所有卡负载均衡
  - 速度快，不受 GIL 限制
  - 需要手动设置 DistributedSampler、torchrun 等

  简单说：DDP 是 DP 的升级版，速度更快、显存更均衡，但配置更复杂。PyTorch
  官方推荐用 DDP。
